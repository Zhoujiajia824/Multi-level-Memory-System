# 评测说明文档

> 本文档描述 VLA Memory Demo 系统的评测方法论、指标定义、轨迹处理策略、
> 统计分析方式、报告格式以及评测的局限性和后续改进方向。

---

## 1. 评测方法论

### 1.1 对比评测框架

本系统采用**对照实验**的方法评测记忆系统对驾驶决策的影响：

| 实验组 | 记忆状态 | 说明 |
|--------|----------|------|
| `memory_on` | 三层记忆全部启用 | 完整的记忆增强决策 |
| `memory_off` | 三层记忆全部关闭 | 仅基于当前帧的基准决策 |

通过对比两组实验的评测指标，量化记忆系统对决策质量的贡献。

### 1.2 评测流程

```
┌────────────────────────────────────────────────────┐
│                    评测流程                          │
├────────────────────────────────────────────────────┤
│                                                    │
│  1. 加载配置和数据集                                 │
│     ├── 读取 evaluation.yaml 配置                  │
│     └── 加载 nuScenes 评测场景列表                  │
│                                                    │
│  2. 对每个场景执行决策                               │
│     ├── 遍历场景的每一帧                             │
│     ├── 生成预测轨迹（memory_on 或 memory_off）     │
│     ├── 加载真值轨迹（ground truth）                │
│     └── 保存预测和真值                               │
│                                                    │
│  3. 计算评测指标                                     │
│     ├── 逐帧计算 ADE、FDE                           │
│     ├── 判断轨迹有效性                               │
│     ├── 判断行为标签准确性                           │
│     └── 汇总所有场景的结果                           │
│                                                    │
│  4. 分组统计                                         │
│     ├── 按场景类型分组                               │
│     ├── 按天气条件分组                               │
│     └── 按行为类型分组                               │
│                                                    │
│  5. 生成评测报告                                     │
│     ├── 输出 JSON 格式的详细结果                     │
│     └── 输出 Markdown 格式的可读报告                 │
│                                                    │
└────────────────────────────────────────────────────┘
```

### 1.3 评测场景选择

评测场景从 nuScenes 验证集中选取，满足以下条件：
- 场景长度 >= 20 帧（至少 10 秒的驾驶数据）
- 包含多种场景类型（直行、路口、高速等）
- 包含多种天气条件（晴天、雨天、夜间等）
- 包含多种驾驶行为（跟车、变道、转弯、停车等）

## 2. 指标定义

### 2.1 ADE（Average Displacement Error，平均位移误差）

ADE 衡量预测轨迹与真值轨迹之间的平均点对点距离。

**公式**：

```
ADE = (1 / N) * Σ(i=1 to N) sqrt((x_pred_i - x_gt_i)^2 + (y_pred_i - y_gt_i)^2)
```

其中：
- N 为轨迹点数量
- `(x_pred_i, y_pred_i)` 为第 i 个预测轨迹点
- `(x_gt_i, y_gt_i)` 为第 i 个真值轨迹点

**单位**：米（m）

**解读**：
- ADE < 1.0m：预测轨迹与真值非常接近
- ADE 1.0~3.0m：预测轨迹有一定偏差，但在可接受范围内
- ADE > 3.0m：预测轨迹偏差较大，可能影响驾驶安全

### 2.2 FDE（Final Displacement Error，终点位移误差）

FDE 衡量预测轨迹终点与真值轨迹终点之间的距离。

**公式**：

```
FDE = sqrt((x_pred_N - x_gt_N)^2 + (y_pred_N - y_gt_N)^2)
```

其中：
- `(x_pred_N, y_pred_N)` 为预测轨迹的最后一个点
- `(x_gt_N, y_gt_N)` 为真值轨迹的最后一个点

**单位**：米（m）

**解读**：
- FDE 通常大于 ADE，因为误差会随时间累积
- FDE < 2.0m：终点预测较准确
- FDE 2.0~5.0m：终点预测有一定偏差
- FDE > 5.0m：终点预测偏差较大

### 2.3 valid_trajectory_rate（有效轨迹率）

有效轨迹率衡量模型输出的轨迹中，格式和内容符合要求的比例。

**判定条件**：

一个轨迹被认为是有效的，当且仅当满足以下所有条件：

1. 航点数量 >= `min_waypoints`（默认 10 个）
2. 所航点的 `t` 值单调递增
3. 所航点的坐标值为有限数值（非 NaN 或 Inf）
4. `x` 坐标不能全部为 0（表示模型未生成有效轨迹）

**公式**：

```
valid_trajectory_rate = 有效轨迹数量 / 总轨迹数量
```

**解读**：
- 有效轨迹率 >= 95%：模型输出稳定性好
- 有效轨迹率 < 90%：模型输出不稳定，需要优化 Prompt 或增加 Fallback

### 2.4 behavior_accuracy（行为准确率）

行为准确率衡量模型预测的驾驶行为与真值行为之间的一致性。

**行为标签集合**：

```python
VALID_BEHAVIORS = [
    "KEEP_LANE",      # 保持车道
    "FOLLOW",         # 跟车
    "STOP",           # 停车
    "TURN_LEFT",      # 左转
    "TURN_RIGHT",     # 右转
    "UNKNOWN",        # 未知行为
]
```

**公式**：

```
behavior_accuracy = 正确预测的行为数量 / 总帧数
```

**注意**：真值行为标签是根据 nuScenes 真值轨迹推导得出的，推导规则如下：
- 速度接近 0 → `STOP`
- 航向角变化 > 30° 且左偏 → `TURN_LEFT`
- 航向角变化 > 30° 且右偏 → `TURN_RIGHT`
- 前方有近距离车辆 → `FOLLOW`
- 其他情况 → `KEEP_LANE`

## 3. 轨迹重采样策略

### 3.1 为什么需要重采样

VLM 输出的轨迹点数量可能不一致（有的帧输出 20 个点，有的输出 30 个），
而真值轨迹的格式也是固定的。为了公平计算 ADE 和 FDE，需要将预测轨迹
和真值轨迹重采样到相同的点数。

### 3.2 重采样算法

采用**线性插值**进行重采样：

```
输入：原始轨迹 traj（N 个点），目标点数 target_num
输出：重采样后的轨迹 resampled（target_num 个点）

算法：
1. 计算原始轨迹的累积弧长 L = [0, l1, l2, ..., l_N]
2. 在 [0, l_N] 上均匀采样 target_num 个点
3. 对每个采样点，通过线性插值计算对应的 (t, x, y) 坐标
```

### 3.3 重采样参数

```yaml
# config/evaluation.yaml
resample:
  target_num: 25        # 重采样目标点数
  method: "linear"      # 插值方法（目前仅支持线性插值）
```

### 3.4 重采样示例

```
原始轨迹（5个点）：
  (0.0, 0.0) → (1.0, 0.5) → (2.0, 1.0) → (3.0, 1.2) → (4.0, 1.0)

重采样为 10 个点（均匀插值）：
  (0.0, 0.0) → (0.44, 0.22) → (0.89, 0.44) → (1.33, 0.67) → ...
```

## 4. 分组统计方式

### 4.1 按场景类型分组

将评测结果按场景类型分组统计，分析记忆系统在不同场景下的效果差异。

| 场景类型 | scene_id | 示例 |
|----------|----------|------|
| 直行道路 | `straight_road` | 城市直路、高速直路 |
| 路口 | `intersection` | 十字路口、T 字路口 |
| 弯道 | `curve` | 弯道行驶 |
| 高速 | `highway` | 高速公路场景 |
| 停车 | `parking` | 停车场场景 |

### 4.2 按天气条件分组

| 天气条件 | weather_id | 说明 |
|----------|------------|------|
| 晴天 | `sunny` | 白天晴天 |
| 雨天 | `rainy` | 下雨天 |
| 夜间 | `night` | 夜间行驶 |
| 多云 | `cloudy` | 阴天 |

### 4.3 按行为类型分组

统计每种驾驶行为的预测准确率和轨迹误差。

### 4.4 统计指标

对每个分组计算以下统计量：

| 统计量 | 说明 |
|--------|------|
| mean | 平均值 |
| median | 中位数 |
| std | 标准差 |
| min | 最小值 |
| max | 最大值 |
| count | 样本数 |

## 5. 报告格式说明

### 5.1 JSON 报告格式

```json
{
    "experiment_name": "memory_on_20240101",
    "config": {
        "memory_enabled": true,
        "model_name": "qwen-vl-max"
    },
    "overall_metrics": {
        "ade": {"mean": 2.15, "median": 1.89, "std": 1.23, "count": 500},
        "fde": {"mean": 4.32, "median": 3.67, "std": 2.45, "count": 500},
        "valid_trajectory_rate": 0.97,
        "behavior_accuracy": 0.72
    },
    "grouped_metrics": {
        "by_scene": {
            "straight_road": {"ade": {"mean": 1.50}, "fde": {"mean": 3.20}},
            "intersection": {"ade": {"mean": 3.20}, "fde": {"mean": 6.10}}
        },
        "by_weather": {
            "sunny": {"ade": {"mean": 2.00}, "fde": {"mean": 4.00}},
            "rainy": {"ade": {"mean": 2.80}, "fde": {"mean": 5.50}}
        }
    }
}
```

### 5.2 Markdown 报告格式

Markdown 报告包含以下部分：

1. **实验概览**：实验名称、配置摘要、评测场景数
2. **总体指标**：ADE、FDE、有效率、行为准确率的汇总表格
3. **分组对比**：按场景/天气/行为的分组对比表格
4. **memory_on vs memory_off**：记忆效果的对比分析
5. **典型案例**：最佳和最差的预测案例展示
6. **结论与建议**：基于评测结果的改进建议

### 5.3 报告输出路径

```
outputs/{experiment_name}/
├── results.json          # JSON 格式详细结果
└── report.md             # Markdown 格式可读报告
```

## 6. 评测局限性和后续改进

### 6.1 当前局限性

| 局限性 | 说明 |
|--------|------|
| 数据集单一 | 目前仅在 nuScenes 上评测，泛化能力未知 |
| 轨迹精度受限 | VLM 输出的轨迹精度有限，难以达到传统规划器的精度 |
| 行为标签推导 | 真值行为标签是从轨迹推导的，可能存在标注噪声 |
| 样本量有限 | nuScenes 验证集的场景数量有限，统计显著性可能不足 |
| 开环评测 | 当前为开环评测（不将预测轨迹用于后续帧），与实际闭环控制存在差异 |
| API 稳定性 | 依赖 VLM API 的可用性和稳定性，API 调用失败可能影响评测结果 |
| 评测成本 | 大规模评测需要大量的 API 调用，成本较高 |

### 6.2 后续改进方向

1. **闭环评测**：将预测轨迹反馈到仿真器中进行闭环评测，更真实地评估系统性能
2. **多数据集评测**：在 Waymo、Argoverse 等数据集上扩展评测
3. **更多指标**：添加碰撞率、路线偏离率、舒适度指标等
4. **细粒度分析**：对长尾场景（如紧急制动、复杂路口）进行专项评测
5. **效率评测**：评测记忆系统的延迟和吞吐量，确保满足实时性要求
6. **消融实验**：逐层关闭记忆，分析各层记忆的独立贡献
7. **人工评测**：引入人类驾驶员的主观评价，补充客观指标
8. **时序一致性评测**：评估相邻帧预测轨迹的一致性，避免决策跳变

### 6.3 评测配置参考

```yaml
# config/evaluation.yaml
evaluation:
  # 评测场景配置
  max_scenes: 50                    # 最大评测场景数（null 表示全部）
  scene_filter: null                # 场景过滤条件

  # 轨迹参数
  resample:
    target_num: 25
    method: "linear"

  # 有效性判断
  min_waypoints: 10                 # 最少轨迹点数

  # 对比实验
  compare_modes:                    # 需要对比的模式
    - memory_on
    - memory_off

  # 输出配置
  output_dir: "outputs"
  save_trajectories: true           # 是否保存每帧的预测和真值轨迹
  save_memory_snapshots: false      # 是否保存记忆快照
```
