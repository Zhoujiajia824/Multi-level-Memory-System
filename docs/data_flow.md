# 数据流说明文档

> 本文档描述 VLA Memory Demo 系统中数据从输入到输出的完整流转过程，
> 包括每个步骤的输入输出格式、数据格式约定和文件存储约定。

---

## 1. 完整数据流图

### 1.1 主数据流（ASCII）

```
┌────────────┐
│ nuScenes   │
│  数据集     │
└─────┬──────┘
      │ 1. 加载场景列表
      ▼
┌────────────────┐
│ NuScenesAdapter │ ──── 场景元信息、帧列表、自车轨迹
└─────┬──────────┘
      │ 2. 逐帧遍历 + 状态构建
      ▼
┌────────────────────┐     ┌──────────────┐
│ EgoStateBuilder    │────>│  FrameMeta   │ ── 图像路径、时间戳
│ TrajectoryBuilder  │     │  EgoState    │ ── 自车位置、速度、航向
│ RouteInfer         │     │  Trajectory  │ ── 历史/未来轨迹
└─────┬──────────────┘     └──────────────┘
      │ 3. 图像特征提取
      ▼
┌────────────────────┐
│ DINOv2Extractor    │ ──── DINOv2 特征向量 (768-d)
│ (DINOv2)           │
└─────┬──────────────┘
      │ 4. 场景理解（VLM）
      ▼
┌─────────────────────────┐     ┌──────────────────┐
│ SceneUnderstandingPipeline│──>│ SceneUnderstanding│
│ (场景理解 VLM)           │    │ - scene_description
└─────┬──────────────┘     │ - scene_id
      │                    │ - weather_id
      │ 5. 存入记忆         │ - surrounding_objects
      ▼                    └──────────────────┘
┌────────────────────────────────────────────┐
│              记忆管理系统                    │
│                                            │
│  ┌──────────────┐  ┌──────────────┐       │
│  │ 短期记忆      │  │ 中期记忆      │       │
│  │ (滑动窗口)    │  │ (FAISS 检索) │       │
│  └──────┬───────┘  └──────┬───────┘       │
│         │                  │               │
│         └────────┬─────────┘               │
│                  │                         │
│         ┌────────┴─────────┐               │
│         │  长期记忆         │               │
│         │  (规则匹配)       │               │
│         └────────┬─────────┘               │
└──────────────────┼─────────────────────────┘
                   │ 6. 构建决策上下文
                   ▼
┌────────────────────┐
│ DecisionClient     │ ──── 决策 VLM 推理
│ (决策 VLM)         │
└─────┬──────────────┘
      │ 7. 解析决策输出
      ▼
┌────────────────────┐     ┌──────────────────┐
│ OutputParser       │────>│ DecisionOutput   │
│ (输出解析器)       │     │ - behavior       │
└─────┬──────────────┘     │ - trajectory     │
      │ 8.（失败则 Fallback）│ - risk_level    │
      ▼                    └──────────────────┘
┌────────────────────┐
│ RuleFallback       │ ──── 安全兜底决策
│ (规则兜底)         │
└─────┬──────────────┘
      │ 9. 评测
      ▼
┌────────────────────┐
│ Evaluator          │ ──── ADE/FDE/有效率
│ (评测模块)         │
└─────┬──────────────┘
      │ 10. 生成报告
      ▼
┌────────────────────┐
│ ReportGenerator    │ ──── Markdown / JSON 报告
└────────────────────┘
```

### 1.2 单帧处理时序

```
时间线 ──────────────────────────────────────────>

帧 N:
  [加载帧数据] → [提取特征] → [场景理解] → [存入记忆] → [检索记忆]
                                                              │
                                                              ▼
                          [构建 Prompt] ← [匹配长期规则] ← [获取记忆上下文]
                              │
                              ▼
                          [VLM 决策] → [解析输出] → [评测对比]
```

## 2. 每个步骤的输入输出格式

### 2.1 数据加载阶段

**步骤 1：加载场景列表**

| 项目 | 说明 |
|------|------|
| 输入 | nuScenes 数据集路径（`config/data_nuscenes.yaml` 中配置） |
| 输出 | 场景列表，每个场景包含：`scene_token`、`description`、`nbr_samples`、`first_frame`、`last_frame` |
| 格式 | Python 字典列表 |

**步骤 2：逐帧解析**

| 项目 | 说明 |
|------|------|
| 输入 | 场景 token，帧索引 |
| 输出 | `KeyFrame`：帧 ID、时间戳、图像路径 |
|      | `EgoState`：x, y, z, speed, yaw, acceleration |
|      | `List[SurroundingObject]`：周围目标列表 |

### 2.2 特征提取阶段

**步骤 3：图像特征提取**

| 项目 | 说明 |
|------|------|
| 输入 | 图像文件路径（`str` 或 `Path`） |
| 输出 | 特征向量（`numpy.ndarray`，shape = `[768]`，L2 归一化） |
| 模型 | DINOv2-base |

### 2.3 场景理解阶段

**步骤 4：场景理解 VLM**

| 项目 | 说明 |
|------|------|
| 输入 | 当前帧图像 + 场景理解 Prompt |
| 输出 | `SceneUnderstanding` 对象 |

`SceneUnderstanding` 结构：
```json
{
    "scene_description": "城市直行道路，前方有车辆缓行",
    "scene_id": "straight_road",
    "weather_id": "sunny",
    "surrounding_objects": [
        {
            "object_id": "veh_001",
            "object_type": "vehicle",
            "distance": 25.0,
            "relative_direction": "front",
            "speed": 3.0,
            "lane_position": "same_lane"
        }
    ],
    "traffic_elements": ["红绿灯（绿灯）", "限速50"]
}
```

### 2.4 记忆管理阶段

**步骤 5：存入记忆**

| 记忆层 | 输入 | 输出 |
|--------|------|------|
| 短期记忆 | `ShortTermMemoryItem`（帧信息+场景描述） | 滑动窗口更新 |
| 中期记忆 | 特征向量 + 元数据 | FAISS 索引更新 |
| 长期记忆 | 场景 ID + 天气 ID | 匹配规则列表 |

**步骤 6：构建决策上下文**

| 项目 | 说明 |
|------|------|
| 输入 | 当前帧数据 + 三层记忆检索结果 |
| 输出 | 决策 Prompt 文本 |

### 2.5 决策阶段

**步骤 7-8：决策 VLM 推理与解析**

| 项目 | 说明 |
|------|------|
| 输入 | 决策 Prompt（含图像、记忆上下文、导航指令） |
| 输出 | `DecisionOutput` 对象 |

`DecisionOutput` 结构：
```json
{
    "behavior": "KEEP_LANE",
    "behavior_reason": "前方道路通畅，保持当前车道",
    "target_speed": 8.0,
    "risk_level": "low",
    "trajectory": [
        {"t": 0.0, "x": 0.0, "y": 0.0},
        {"t": 0.1, "x": 0.8, "y": 0.0},
        ...
    ],
    "safety_notes": ["注意前方路口"]
}
```

### 2.6 评测阶段

**步骤 9-10：评测与报告**

| 项目 | 说明 |
|------|------|
| 输入 | 预测轨迹列表 + 真值轨迹列表 + 行为标签 |
| 输出 | 评测指标字典 + Markdown 报告 |

## 3. 数据格式约定

### 3.1 坐标系统

| 约定项 | 说明 |
|--------|------|
| 坐标系 | 自车坐标系（ego-centric），原点为自车当前位置 |
| X 轴 | 自车正前方 |
| Y 轴 | 自车正左方 |
| Z 轴 | 垂直地面向上 |
| 单位 | 米（m） |
| 角度单位 | 弧度（rad），范围 [-π, π] |
| 航向角（yaw） | 正前方为 0，逆时针为正 |

### 3.2 时间戳

| 约定项 | 说明 |
|--------|------|
| 时间戳格式 | 微秒（microsecond），Unix 时间戳 |
| 时间间隔 | 轨迹点间隔 0.1 秒（100ms） |
| 预测范围 | 2.5 秒（25 个轨迹点） |
| 帧率 | 2 Hz（nuScenes 关键帧间隔 0.5 秒） |

### 3.3 速度与加速度

| 约定项 | 说明 |
|--------|------|
| 速度单位 | 米/秒（m/s） |
| 加速度单位 | 米/秒²（m/s²） |
| 角速度单位 | 弧度/秒（rad/s） |
| 目标速度范围 | [0, 30] m/s（约 0-108 km/h） |

### 3.4 距离与尺寸

| 约定项 | 说明 |
|--------|------|
| 距离单位 | 米（m） |
| 目标距离 | 自车中心到目标中心的欧氏距离 |
| 车辆尺寸 | nuScenes 原始标注中的 bbox 尺寸 |

### 3.5 轨迹格式

轨迹由一系列航点（Waypoint）组成：

```python
# 单个航点
Waypoint:
    t: float    # 时间偏移（秒），相对于当前帧
    x: float    # X 坐标（米），自车坐标系
    y: float    # Y 坐标（米），自车坐标系

# 完整轨迹
Trajectory:
    waypoints: List[Waypoint]   # 航点列表，按 t 升序
```

**轨迹约束**：
- 最少 10 个航点
- 推荐 25 个航点（2.5 秒 @ 0.1 秒间隔）
- `t` 必须单调递增
- `x` 坐标在正常行驶时通常为正值（前进方向）

## 4. 文件存储约定

### 4.1 输出文件格式

| 文件类型 | 格式 | 说明 |
|----------|------|------|
| 评测结果 | JSON | 所有场景的指标汇总 |
| 评测报告 | Markdown | 可读性强的评测报告 |
| 轨迹数据 | JSON | 每帧的预测轨迹和真值轨迹 |
| 记忆快照 | JSON | 记忆状态导出 |
| FAISS 索引 | `.index` | FAISS 二进制索引文件 |
| 日志文件 | `.log` | 运行日志 |

### 4.2 输出文件路径

```
outputs/
├── {experiment_name}/                # 实验名称（如 "memory_on_20240101"）
│   ├── config_snapshot.yaml          # 本次实验的配置快照
│   ├── results.json                  # 评测结果（JSON 格式）
│   ├── report.md                     # 评测报告（Markdown 格式）
│   ├── trajectories/                 # 轨迹数据
│   │   ├── {scene_token}/
│   │   │   ├── frame_{idx}_pred.json # 预测轨迹
│   │   │   └── frame_{idx}_gt.json   # 真值轨迹
│   │   └── ...
│   ├── memories/                     # 记忆快照
│   │   ├── short_term.json           # 短期记忆导出
│   │   ├── mid_term_meta.json        # 中期记忆元数据
│   │   └── faiss_index.index         # FAISS 索引文件
│   └── logs/
│       └── run.log                   # 运行日志
```

### 4.3 配置文件约定

所有配置文件使用 YAML 格式，遵循以下约定：

```yaml
# 配置文件结构示例
section_name:             # 模块名称（小写+下划线）
  param_name: value       # 参数名（小写+下划线）
  nested:                 # 嵌套配置
    key: value

# 所有路径配置使用相对路径（相对于项目根目录）
# 布尔值使用 true/false（小写）
# 数值类型明确标注单位
```

### 4.4 知识文件格式

长期记忆的知识规则存储在 `knowledge/` 目录下，使用 YAML 格式：

```yaml
# knowledge/rules.yaml 示例
rules:
  - rule_id: "R001"
    title: "安全车距规则"
    description: "在城市道路上行驶时，与前车保持至少 2 秒的安全时距"
    scene_id: "all"          # 适用场景，"all" 表示所有场景
    weather_id: "all"        # 适用天气
    priority: 1              # 优先级（1 最高）
    condition: "前方有车辆且速度 > 5 m/s"
    action: "保持车距，准备减速"
```

### 4.5 FAISS 索引文件

| 项目 | 说明 |
|------|------|
| 文件路径 | `outputs/{experiment}/memories/faiss_index.index` |
| 索引类型 | `IndexFlatIP`（内积索引，配合 L2 归一化等价余弦相似度） |
| 向量维度 | 768（与 DINOv2-base 输出一致） |
| 元数据文件 | `mid_term_meta.json`（存储向量 ID 到帧信息的映射） |

## 5. 数据校验规则

系统在数据处理过程中会进行以下校验：

1. **帧数据校验**：确保每帧包含完整的图像路径和自车状态
2. **特征向量校验**：确保向量维度正确且已 L2 归一化
3. **场景理解校验**：确保 `scene_id` 和 `weather_id` 属于预定义集合
4. **轨迹校验**：确保航点数量、时间单调性、坐标合理性
5. **决策输出校验**：确保 `behavior` 属于有效行为集合
6. **风险等级校验**：确保 `risk_level` 为 `low`/`medium`/`high` 之一
